Resumen del Proyecto

🚀

¿Qué es Snipe-IT?

Snipe-IT es una aplicación web de código abierto, desarrollada y mantenida por la empresa Grokability, Inc., que se ha consolidado como una de las soluciones líderes a nivel mundial para la Gestión de Activos de Tecnologías de la Información (IT Asset Management — ITAM). Su propósito fundamental es permitir a las organizaciones llevar un control completo y centralizado sobre todos los recursos tecnológicos que poseen.

En la práctica, el sistema permite registrar, rastrear y administrar activos de diversa naturaleza, tales como: laptops, monitores, impresoras, teclados, mouse, servidores, teléfonos IP, proyectores, así como licencias de software (por ejemplo, Microsoft Office o Adobe Creative Cloud). Cada activo queda vinculado a un usuario responsable, una ubicación física y un historial completo de movimientos y asignaciones.

🎯

Problema que Resuelve

En muchas instituciones —universidades, empresas, hospitales— el inventario de equipos tecnológicos se gestiona de forma manual mediante hojas de cálculo o registros en papel. Este método es propenso a errores humanos, duplicaciones y pérdida de información. Cuando un equipo se avería, se pierde o cambia de manos, no existe un registro confiable que indique quién lo tiene, cuándo fue asignado o cuándo expira su garantía.

Snipe-IT reemplaza esos procesos obsoletos por una plataforma web centralizada y autoalojable, donde cualquier movimiento de activos —asignaciones, devoluciones, mantenimientos— queda registrado automáticamente. Además, incorpora funcionalidades avanzadas como el cálculo de depreciación financiera, alertas de vencimiento de licencias y generación de reportes auditables para cumplimiento normativo.

🔍

¿Por qué se seleccionó para Pruebas?

El sistema Snipe-IT fue seleccionado como objeto de estudio para el presente trabajo porque cumple satisfactoriamente con los criterios establecidos en el proyecto del curso de Pruebas de Software. La plataforma representa un entorno empresarial real que permite aplicar metodologías de aseguramiento de calidad, automatización de pruebas y prácticas DevOps dentro de un contexto académico controlado.

En primer lugar,el proyecto utiliza la licencia GNU Affero General Public License v3.0 (AGPL-3.0), la cual permite realizar fork, modificación, distribución y uso académico del sistema sin restricciones para fines educativos.

En segundo lugar, Snipe-IT cumple con el criterio de dominio empresarial solicitado en el curso, ya que se trata de un sistema de gestión de activos tecnológicos.

  • Laptops, computadoras de escritorio, monitores e impresoras, etc.

Asimismo, el proyecto posee un stack tecnológico moderno y ampliamente utilizado en la industria del desarrollo de software:

  • Backend: PHP 8.2 y Laravel 12
  • Base de datos: MySQL, MariaDB y PostgreSQL
  • Frontend: Blade, Bootstrap y JavaScript
  • Arquitectura: API REST y patrón MVC
  • Contenedores: Docker y Docker Compose
  • CI/CD: GitHub Actions

De igual manera, Snipe-IT cumple con el nivel de complejidad media-alta requerido por el curso, debido a que posee más de 40 modelos, más de 400 migraciones

Finalmente, el sistema incorpora una infraestructura DevOps adaptable que facilita la automatización del proceso de pruebas y la integración continua:

  • Docker Compose para despliegue local
  • GitHub Actions para pipelines CI/CD
  • PHPUnit para pruebas automatizadas
  • Pipelines de testing automatizado
  • Herramientas de análisis estático de código

En consecuencia, Snipe-IT representa un caso de estudio adecuado para implementar y evaluar pruebas unitarias, pruebas de integración y prácticas de calidad de software utilizando metodologías ágiles Scrum y procesos DevOps automatizados.

Arquitectura del Sistema

Flujo de Control MVC

Snipe-IT se fundamenta en una arquitectura MVC desacoplada, donde el flujo de las peticiones sigue un camino estructurado de seguridad y procesamiento:

Cliente Web/API
➔
Middleware (Filtros/2FA/SAML)
➔
Routes (Web & API)
➔
Controllers (Web & API)
➔
Models & Policies (Eloquent/Rules)
➔
Database (MySQL/PG)

Componentes del Código

  • Modelos (app/Models/): Representan las entidades lógicas como Asset, User, License, Accessory, Consumable, y Component. Contienen las relaciones Eloquent y las reglas de negocio base.
  • Controladores (app/Http/Controllers/): Divididos en controladores Web (para renderizado de plantillas Blade) y controladores API (ubicados en el namespace de la API para devolver respuestas JSON estructuradas).
  • Vistas (resources/views/): Construidas sobre Blade y extendidas con el layout AdminLTE y estilos responsivos basados en Bootstrap 3.

Filtros de Seguridad & API

  • Middleware: Encargado de la seguridad perimetral del sistema. Controla la autenticación de sesión, protección CSRF, localización de lenguaje dinámica, políticas de autenticación en dos factores (2FA), y herencia de permisos.
  • API REST v1 (/api/v1/): Expone endpoints seguros para interactuar programáticamente con los recursos de hardware, usuarios, licencias, accesorios, consumibles, y reportes.

Carpetas Clave para Control de Calidad

📂 app/

Contiene toda la lógica que será sujeta a pruebas de backend. Es el núcleo analizado en búsqueda de vulnerabilidades y defectos lógicos.

📂 database/

Vital para las pruebas unitarias y de integración. Contiene las fábricas de datos (Factories) y semillas (Seeders) que inicializan la DB en entornos limpios.

📂 tests/

Directorio clave para la ejecución del plan de pruebas. Alberga los test suites unitarios e integrales ejecutables con PHPUnit.

Funcionalidades

Módulos del Sistema & Riesgo Asociado

💻 Muy Alto

Assets (Activos)

Gestión integral de hardware. Permite el CRUD, auditoría de campo, depreciación financiera, check-in/check-out y asignación de historial.

👥 Muy Alto

Users (Usuarios)

Gestión de identidades y accesos. Controla los roles, permisos granulares, sincronización LDAP, OAuth2, SAML y 2FA.

🔑 Alto

Licenses (Licencias)

Control de licencias de software, administración de asientos (seats), monitoreo de cumplimiento legal y alertas de expiración.

🖱️ Medio

Accessories (Accesorios)

Gestión de periféricos (teclados, mouse, cables). Rastreable en volumen, sin necesidad de números de serie únicos.

🖨️ Medio

Consumables (Consumibles)

Administración de materiales consumibles (tóner, hojas). Flujo de control simple para stock mínimo y reabastecimiento.

💾 Medio

Components (Componentes)

Gestión de hardware interno (memorias RAM, discos SSD) que se instalan y asocian directamente a un Activo principal.

📈 Alto

Reports (Reportes)

Generación de informes operativos, contables y de auditoría. Soporta exportaciones en formato PDF y hojas de cálculo (CSV/Excel) con cálculos de depreciación dinámicos.

Despliegue e Integración

Arquitectura DevOps

Contenedores & Ambientes

  • Configuración Docker: El proyecto provee un Dockerfile y archivos de orquestación docker-compose.yml multiplataforma que levantan el entorno completo en segundos.
  • Imágenes Soportadas: Uso de distribuciones basadas en Ubuntu y Alpine optimizadas para PHP, asegurando consistencia de ambientes.
  • Variables de Entorno Clave (.env): Controla aspectos críticos como APP_ENV, la conexión de DB (DB_CONNECTION), pasarelas de correo (MAIL_HOST), motores de caché, límites de API (API_THROTTLE), y adaptadores de SAML/LDAP.

Pruebas y Automatización

  • PHPUnit Suite: Configurado para orquestar pruebas bajo dos suites principales: Unit (pruebas lógicas aisladas) y Feature (pruebas de integración de punta a punta en base de datos in-memory SQLite).
  • GitHub Actions Pipelines: Pipelines robustos que ejecutan pruebas paralelas en diferentes motores de base de datos y validan vulnerabilidades.

Análisis de Riesgos

Componentes Críticos para Pruebas

Componentes con Mayor Nivel de Crítica

Hemos priorizado el esfuerzo de diseño de casos de prueba sobre los componentes cuya falla afectaría críticamente la integridad o confidencialidad de la aplicación:

1

Autenticación & 2FA

Riesgo de escalamiento de privilegios, bypass de doble factor y fallos de comunicación en los proveedores LDAP/SAML.

2

Proceso Checkout / Checkin

Integridad lógica de la base de datos: validación de asignaciones duplicadas de hardware, y registro inquebrantable de historial de transacciones.

3

Permisos del Sistema

Fugas de acceso a datos multi-company (multi-tenant lógico) y asimilación de herencias de roles administrativos.

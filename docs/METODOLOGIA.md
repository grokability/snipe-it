# Metodología de Trabajo

## Introducción

Para el desarrollo del proyecto de pruebas de software sobre Snipe-IT, el equipo aplicará prácticas ágiles basadas en Scrum junto con principios DevOps para garantizar una gestión eficiente del trabajo, colaboración continua y control de calidad del software.

## Metodología Scrum

Scrum será utilizado como marco de trabajo para organizar las actividades del proyecto mediante iteraciones cortas llamadas Sprints.

### Roles

| Rol                  | Responsabilidad                                                              |
| -------------------- | ---------------------------------------------------------------------------- |
| Scrum Master         | Coordinar las actividades del Sprint y facilitar la comunicación del equipo. |
| Equipo de Desarrollo | Ejecutar las tareas técnicas asignadas y cumplir los objetivos del Sprint.   |
| Equipo de Pruebas    | Diseñar, documentar y ejecutar los casos de prueba definidos.                |

### Eventos Scrum

#### Sprint Planning

Reunión inicial donde se definen los objetivos, tareas y entregables del Sprint.

#### Daily Scrum

Reuniones breves para revisar el avance de las actividades y detectar impedimentos.

#### Sprint Review

Presentación de los resultados obtenidos durante el Sprint.

#### Sprint Retrospective

Análisis de mejoras para optimizar el trabajo del siguiente Sprint.

## Gestión del Trabajo

El equipo utilizará GitHub Projects como tablero Kanban para organizar las tareas en los estados:

* Backlog
* To Do
* In Progress
* Review
* Done

Cada actividad será registrada mediante GitHub Issues para facilitar el seguimiento y control del avance.

## Prácticas DevOps

Se aplicarán prácticas DevOps para automatizar y mejorar el flujo de desarrollo:

* Uso de Git para control de versiones.
* Gestión colaborativa mediante GitHub.
* Uso de Pull Requests para revisión de cambios.
* Integración continua mediante GitHub Actions (en fases posteriores).
* Documentación continua mediante GitHub Wiki y GitHub Pages.

## Beneficios Esperados

* Mejor organización del trabajo.
* Seguimiento continuo del avance.
* Mayor calidad del software mediante pruebas sistemáticas.
* Colaboración eficiente entre los integrantes del equipo.
* Documentación centralizada y accesible.

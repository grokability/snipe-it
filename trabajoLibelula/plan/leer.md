Instrucciones:

   - arquitectura gene
   ral
   - stack tecnológico
   - estructura de carpetas
   - módulos o subsistemas realmente existentes
   - configuración de pruebas actual
   - CI/CD existente
   - documentación existente
   - grado real de actividad del proyecto

2. Compara el repositorio contra el contexto del curso y determina:
   - qué parte del proyecto es razonable cubrir en el curso
   - qué módulos sí deben entrar al alcance
   - qué módulos deben quedar fuera por tamaño o por falta de tiempo
   - qué entregables del curso se pueden sustentar de forma realista

3. No asumas procedimientos de planificación por tu cuenta.
   - Si algo no está claro en el repositorio, analízalo antes de inventarlo.
   - Si un plan anterior contradice el código real, prioriza el código real y reporta la diferencia.
   - Si el proyecto es demasiado grande, delimita un alcance académico defendible.

4. Como salida, entrégame:
   - diagnóstico técnico del proyecto
   - alcance recomendado para el curso
   - módulos priorizados para pruebas
   - riesgos o limitaciones reales
   - recomendación de qué plan debe rehacerse desde cero

Importante:
- No generes todavía el plan final.
- No escribas todavía casos de prueba.
- No implementes todavía código.
- Primero entiende el proyecto real y define el alcance correcto.

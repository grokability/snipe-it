OBJETIVO Implementar el proceso de pruebas de software unitarias, integración, sistemas y de aceptación que integre la metodología ágil Scrum con prácticas DevOps automatizadas, aplicado sobre un proyecto de código abierto con licencia MIT/GPL obtenido de GitHub, con el propósito de que el estudiante comprenda, analice y ponga en práctica un proceso de pruebas completo aplicado a un producto de software. 
DESCRIPCIÓN DEL PROYECTO El Grupo de estudiantes deberá seleccionar un producto de software de código abierto disponible en GitHub (con documentación técnica y actividad reciente). A partir de este sistema, deberá analizar el estado actual del proyecto, identificar funcionalidades principales y arquitectura existente, e implementar un proceso de pruebas de software completo que integre el marco de trabajo Scrum + buenas prácticas DevOps 
PRODUCTO DE SOFTWARE Y USO DE HERRAMIENTAS 
3.1. Criterios de la selección del software open source 
• Licencia MIT/GPL verificada: permite fork, modificación y uso libre sin restricciones académicas. 
• Dominio conocido: de preferencia sistemas empresariales para pequeñas y/o medianas empresas, aplicado a cualquier rubro educación, salud, finanzas, educación, comercial, sociales, etc. 
• Stack tecnológico moderno: tecnologías frontend y backend open source vigentes usados en la industria de software actual. 
• Complejidad: mediana el producto de software debe tener de 3 a 5 módulos o subsistemas entre 10 KLOC y 50 KLOC 
• Infraestructura DevOps adaptable: de preferencia el proyecto debe incluir Docker Compose, para facilitar la configuración del pipeline. 
3.2. Herramientas para Scrum y DevOps open-source El proyecto debe incluir el uso de las siguientes herramientas tecnológicas para la implementación del proceso de pruebas ágil con Scrum y buenas prácticas de automatización DevOps:

Herramienta ¿Qué es? ¿Para qué sirve en el proyecto?
GitHub Projects El tablero Kanban/Scrum del equipo. Es donde se organiza todo el trabajo: qué hay que hacer, quién lo hace y en qué estado está. Gestionar el Product Backlog, armar los Sprints, asignar historias de usuario a cada integrante y ver el progreso en tiempo real.

GitHub Actions Automatización CI/CD. Ejecuta tareas automáticas cada vez que alguien sube código al repositorio. Compilar el código, correr las pruebas, detectar errores y desplegar la app a staging — proceso automático.
GitHub Wiki Sistema de documentación colaborativa integrado en el repositorio. Permite crear documentos con múltiples secciones en formato Markdown, editables por todo el equipo. Crear y mantener planes de pruebas, documentación de requisitos, especificaciones técnicas, informes de pruebas y manuales del sistema — todo en un lugar centralizado y versionado.
GitHub Pages El servidor de publicación gratuito de GitHub. Convierte el contenido de tu repositorio en un sitio web accesible públicamente desde internet. Publicar el entorno de staging (demo pública del Sprint), la documentación técnica del proyecto y el burndown chart generado por GitHub Actions.
GitHub Issues El sistema de tickets del proyecto. Cada "issue" representa una tarea, historia de usuario, bug o mejora que el equipo necesita atender. Registrar las historias de usuario del Product Backlog, reportar bugs encontrados en testing y documentar decisiones técnicas del sprint.
